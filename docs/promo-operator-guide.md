# 단톡 홍보 예약 — 운영 설명서

카카오톡 PC에 로그인된 계정으로, 정해 둔 시각에 단톡방마다 홍보를 넣습니다.
수집이 끝난 뒤 댄스인포 방에 완료 메시지를 보내는 기능과는 별개입니다. 홍보 문구와 이미지는 그때그때 이 설명서의 예약 파일만 바꾸면 됩니다.

한 방에는 말풍선이 아래 순서로 나갑니다. 비어 있는 항목은 건너뜁니다.

1. 공통 이미지
2. 공통 홍보 문구
3. 그 방 바로가기 주소
4. 그 방만의 추가 이미지 (있을 때만)
5. 그 방만의 추가 문구 (있을 때만)
6. 그 방만의 추가 바로가기 주소 (있을 때만)

바로가기 주소는 문구 안에 넣지 않습니다. 주소만 따로 보내야 카카오톡 링크 미리보기가 붙습니다.

## 1. 보내기 전에 확인

- 홍보를 돌릴 PC에서 카카오톡 PC가 켜져 있고, 그 계정으로 로그인되어 있어야 합니다.
- 화면 잠금이 없어야 합니다. 실행이 시작되면 마우스와 키보드를 다른 곳에 쓰지 않습니다. 다른 창을 누르면 그 방은 실패합니다.
- 그 계정이 각 단톡방에 들어 있고, 글을 쓸 수 있어야 합니다. 쓰기 권한이 막힌 오픈채팅은 전송이 되지 않습니다.
- 포스터 수집이 돌아가는 시간과 겹치면 안 됩니다. 수집과 홍보가 같은 카카오톡 창을 누릅니다. 작업 스케줄러에서 수집 작업 시간을 보고, 그 앞뒤로 여유를 둡니다.
- 원격 데스크톱으로 붙여 둔 경우, 연결을 끊으면 클릭이 멈춥니다. 보낼 동안은 연결을 유지합니다.

## 2. 쓰는 파일

폴더는 `F:\site_kdance\TEST_web\kakao-pc-collect` 입니다.

| 파일 | 누가 만지나 | 역할 |
|------|-------------|------|
| `config\rooms.yaml` | 방을 새로 넣을 때만 | 방 아이디와 카카오톡 검색어 연결. 홍보 파일의 `id`는 여기 있는 아이디만 쓸 수 있습니다 |
| `config\coords.yaml` | 클릭이 어긋날 때만 | 카카오톡 창에서 검색창·첫 검색 결과·입력칸을 누르는 위치 |
| `config\promo.example.yaml` | 고치지 않음 | 빈 예시. 복사만 합니다 |
| `data\promo\예약이름.yaml` | 홍보할 때마다 | 시각, 공통 이미지, 공통 문구, 방별 주소 |
| `data\promo\` 안의 이미지 | 홍보할 때마다 | 예약 파일과 같은 폴더에 둡니다 |
| `data\promo\예약이름.yaml.sent.json` | 프로그램이 자동 생성 | 어느 방에 보냈는지. 사람이 문구를 적는 파일이 아닙니다 |
| `.env` | 홍보 문구와 무관 | 수집용 설정. 홍보 문장·이미지·주소는 여기 적지 않습니다 |
| `.venv\Scripts\kakao-pc-collect.exe` | 실행 파일 | 아래 명령은 이 파일을 호출합니다 |

`data` 폴더는 저장소에 올라가지 않습니다. PC에만 있습니다.

## 3. 방 연결

홍보 파일에는 카카오톡 방 제목을 직접 적지 않습니다. `id`만 적으면, 프로그램이 `config\rooms.yaml`에서 검색어를 찾아 채팅 탭으로 그 방을 엽니다.

검색어는 카카오톡 검색의 첫 번째 결과가 그 방이어야 하고, 열린 창 제목에 그 검색어가 그대로 들어 있어야 합니다. 다르면 그 방은 보내지 않고 오류로 남깁니다.

2026-11-20 기준 `config\rooms.yaml` 목록입니다. 파일을 고친 뒤에는 파일 내용이 이 표보다 우선합니다.

| 홍보 파일에 쓸 id | 카카오톡에서 찾는 검색어 |
|-------------------|--------------------------|
| `danceinfo_registration` | 댄스인포 행사.강습 등록방 |
| `gangnam_latin` | 강남 라틴클럽 |
| `gangnamton_news` | 강남턴 소식방 |
| `hongdae_bonita` | 홍대보니따 오픈채팅방 |
| `info_latin_korea` | (전국라틴댄스) |
| `gyeonggi_latin_news` | 경기라틴소식방 |
| `hongton_latin` | 홍턴 라틴클럽 |
| `musica_bachata` | musica bachata |
| `ksf_salva_tour` | K.S.F 해외 살바키투어 |

`rooms.yaml`의 `enabled`는 수집 대상인지입니다. 홍보는 이 값과 상관없이, 예약 파일 `rooms`에 적힌 방이면 보냅니다.

수집은 하지 않고 홍보만 할 방은 `enabled: false`로 둡니다. `enabled: true`로 두면 다음 포스터 수집도 그 방을 엽니다.

### 이미 있는 방에 홍보만 할 때

위 표의 id를 예약 파일에 넣고, 그 방 주소만 적습니다. `rooms.yaml`은 수정하지 않습니다.

### 새 방을 추가할 때

1. 카카오톡에서 그 방 이름을 검색합니다. 첫 결과가 그 방인 짧은 문구를 고릅니다. 다른 방과 겹치는 단어는 쓰지 않습니다.
2. `config\rooms.yaml` 맨 아래 방에 이어서 넣습니다. 띄어쓰기는 기존 방과 같게 맞춥니다.

```yaml
  - id: new_room_id
    search: "방 제목에 실제로 있는 고유 문구"
    enabled: false
    room_type: open
```

- `id`는 영문·숫자·밑줄. 한 번 정하면 예약 파일에서 이 값을 씁니다.
- `search`는 따옴표로 감쌉니다.
- 오픈채팅이면 `room_type: open`, 일반 단톡이면 `room_type: general`입니다. 이 값은 홍보 전송이 아니라 이후 사진 수집에 쓰입니다.
- 홍보만 할 거면 `enabled: false`, 포스터 수집에도 넣을 거면 `enabled: true`입니다.

3. 예약 파일에 같은 id와 주소를 넣습니다.
4. 본전송 전에 그 방 하나만 `--now`로 시험합니다. 아래 6절입니다.

## 4. 예약 파일 만들기

1. 폴더를 만듭니다. `F:\site_kdance\TEST_web\kakao-pc-collect\data\promo`
2. `config\promo.example.yaml`을 그 폴더로 복사합니다. 날짜가 보이게 이름을 바꿉니다. 예: `20261121.yaml`
3. 이미지를 같은 폴더에 넣습니다. 예: `poster.jpg`. jpg, png를 사용할 수 있습니다.
4. 복사한 yaml을 메모장으로 열어 아래처럼 고칩니다. 콜론 뒤 띄어쓰기, 줄 들여쓰기를 유지합니다.

```yaml
id: 20261121-week
send_at: "2026-11-21 10:00"
image: poster.jpg
body: |
  11월 넷째 주 강습·파티 안내입니다.
  일정과 장소는 아래 링크에서 확인하세요.
rooms:
  - id: gangnam_latin
    url: "https://danceinfo.net/lessons"
  - id: hongdae_bonita
    url: "https://danceinfo.net/lessons"
    image2: poster-extra.jpg
    body2: |
      이 방 추가 안내입니다.
    url2: "https://danceinfo.net/"
```

항목 의미는 다음과 같습니다.

| 항목 | 필수 | 설명 |
|------|------|------|
| `id` | 아니오 | 이 예약의 이름. 비우면 파일 이름을 씁니다 |
| `send_at` | 아니오 | 보낼 시각. PC 시계 기준 `2026-11-21 10:00`. 따옴표를 유지합니다. 이 줄을 지우면 명령을 실행한 순간에 바로 보냅니다 |
| `image` | 아니오 | 모든 방에 보낼 공통 이미지 파일 이름. 예약 파일과 같은 폴더 |
| `body` | 아니오 | 모든 방에 보낼 공통 문구. `\|` 다음 줄부터 적고, 줄 앞에 띄어쓰기 2칸을 유지합니다 |
| `rooms` | 예 | 보낼 방 목록. 한 칸도 없으면 오류입니다 |
| `rooms`의 `id` | 예 | 3절 표에 있는 id |
| `url` | 그 방에 바로가기를 넣을 때 | `https://`로 시작하는 주소만. 설명 문장을 붙이지 않습니다 |
| `image2` | 아니오 | 그 방만 추가로 보낼 이미지 |
| `body2` | 아니오 | 그 방만 추가로 보낼 문구 |
| `url2` | 아니오 | 그 방만 추가로 보낼 주소 |

공통 이미지나 공통 문구를 비우고, 방마다 주소만 적어도 됩니다. 다만 한 방에 이미지·문구·주소·추가 항목이 전부 없으면 그 예약은 오류로 끝납니다.

이미지의 긴 쪽이 1920픽셀보다 크면, 카카오톡에 붙일 때만 줄입니다. 폴더에 있는 원본 파일은 그대로입니다.

## 5. 보내기 전에 내용 확인

카카오톡 창은 열지 않습니다. 문구와 순서가 맞는지 화면에 출력만 합니다. `send_at` 이전이어도 확인할 수 있습니다.

PowerShell을 열고 아래를 실행합니다. 파일 이름이 다르면 `20261121.yaml`만 바꿉니다.

```powershell
cd F:\site_kdance\TEST_web\kakao-pc-collect
.\.venv\Scripts\kakao-pc-collect.exe promo --campaign data\promo\20261121.yaml --dry-run
```

정상일 때 마지막에 `"status": "dry_run"`이 보입니다. 방마다 `steps` 안에 `image`, `body`, `url` 순서가 있고, 추가분을 적은 방만 `image2`, `body2`, `url2`가 뒤에 붙습니다. `text`에 문구와 주소가 보입니다.

`"status": "missing_image"`이면 이미지 파일 이름이 예약 파일과 다르거나, 같은 폴더에 없습니다. 카카오톡에는 아무것도 나가지 않습니다.

`rooms.yaml 에 없는 방 id`라는 문장이 나오면 3절 표와 id 철자를 비교합니다.

## 6. 한 방으로 먼저 시험

예약 시각을 기다리지 않고, 방 하나에만 바로 보냅니다. 카카오톡 PC를 앞에 두고, 시험이 끝날 때까지 마우스와 키보드를 쓰지 않습니다.

```powershell
cd F:\site_kdance\TEST_web\kakao-pc-collect
.\.venv\Scripts\kakao-pc-collect.exe promo --campaign data\promo\20261121.yaml --room gangnam_latin --now
```

`--room` 뒤의 id만 바꿉니다. 여러 방이면 `--room`을 반복합니다.

```powershell
.\.venv\Scripts\kakao-pc-collect.exe promo --campaign data\promo\20261121.yaml --room gangnam_latin --room hongdae_bonita --now
```

끝날 때 `"status": "sent"`이면 그 방 전송이 끝난 것입니다. 카카오톡에서 이미지, 문구, 주소가 각각 말풍선으로 보이는지 확인합니다.

같은 폴더에 `20261121.yaml.sent.json`이 생깁니다. 여기에 `"ok": true`인 방은 다음 실행에서 다시 보내지 않습니다.

## 7. 시각 예약

5절 확인과 6절 한 방 시험이 끝난 뒤에 예약합니다.

작업 스케줄러를 열고 작업 만들기를 선택합니다.

| 항목 | 값 |
|------|-----|
| 이름 | 댄스인포 단톡 홍보 |
| 보안 옵션 | 사용자의 로그온 여부와 관계없이 실행은 선택하지 않습니다. 로그온한 동안에만 실행합니다 |
| 가장 높은 수준의 권한으로 실행 | 끄기. 켜면 카카오톡 창을 누르지 못합니다 |
| 트리거 | 10분마다, 무기한 |
| 프로그램 | `F:\site_kdance\TEST_web\kakao-pc-collect\.venv\Scripts\kakao-pc-collect.exe` |
| 인수 추가 | `promo --campaign F:\site_kdance\TEST_web\kakao-pc-collect\data\promo\20261121.yaml` |
| 시작 위치 | `F:\site_kdance\TEST_web\kakao-pc-collect` |

파일 이름이 다르면 인수의 yaml 이름만 바꿉니다. `--now`와 `--force`는 스케줄에 넣지 않습니다.

동작은 다음과 같습니다.

- `send_at` 전에는 카카오톡을 열지 않고 `not_due`로 끝납니다.
- 시각이 지난 뒤 첫 실행에서 아직 성공하지 않은 방에 보냅니다.
- 성공한 방은 `yaml파일이름.sent.json`에 남고, 10분 뒤 실행은 `already_sent`로 끝납니다.
- 일부 방만 실패하면 다음 10분 실행이 실패 방만 다시 시도합니다. 성공한 방의 기록을 지우지 않습니다.

다른 주로 내용을 바꿀 때는 파일을 새로 만듭니다. 예: `20261128.yaml`. 스케줄 인스의 파일 이름도 바꿉니다. 새 파일은 보낸 기록이 없으므로 시각이 되면 다시 나갑니다.

같은 파일을 고쳐 다시 쓰려면, 그 파일 옆의 `.sent.json`을 지웁니다. 지우지 않으면 문구를 바꿔도 나가지 않습니다. 일부만 실패했을 때 기록 파일 전체를 지우면, 이미 받은 방에도 한 번 더 나갑니다.

## 8. 화면에 나오는 상태

| status | 의미 | 다음에 할 일 |
|--------|------|----------------|
| `dry_run` | 확인만 함. 카카오톡에는 없음 | 문구·순서가 맞으면 시험 전송 |
| `not_due` | 아직 `send_at` 전 | 정상입니다. 기다립니다 |
| `sent` | 이번 대상 방을 모두 보냄 | 카카오톡에서 말풍선을 확인합니다 |
| `already_sent` | 대상 방이 이미 성공 기록에 있음 | 다시 보내려면 7절처럼 기록 파일을 지우거나, 한 번만 `--force`를 붙여 실행합니다 |
| `missing_image` | 이미지 파일을 찾지 못함 | 파일 이름과 폴더를 예약 파일과 맞춥니다. 아무것도 나가지 않은 상태입니다 |
| `partial` | 일부 방만 실패 | 기록 파일에서 `"ok": false`인 방만 봅니다. 다음 실행이 그 방을 다시 시도합니다 |

다시 한 번만 모두 보낼 때:

```powershell
cd F:\site_kdance\TEST_web\kakao-pc-collect
.\.venv\Scripts\kakao-pc-collect.exe promo --campaign data\promo\20261121.yaml --force
```

시각 전이면 `--force`만으로는 나가지 않습니다. 지금 보내려면 `--now`를 함께 붙입니다.

## 9. 실패했을 때

| 화면에 보이는 말 | 확인할 곳 |
|------------------|-----------|
| `rooms.yaml 에 없는 방 id` | 예약 파일 id가 3절 표와 같은지 |
| `캠페인에 없는 방 id` | `--room`에 적은 id가 예약 파일에 있는지 |
| `missing_image` 또는 파일 경로 | 이미지 파일이 yaml과 같은 폴더에 있는지, 이름 철자가 같은지 |
| `title_mismatch` | 검색어가 방 제목에 그대로 있는지. 카카오톡 검색 첫 결과가 다른 방이면 `rooms.yaml`의 `search`를 더 긴 고유 문구로 바꿉니다 |
| `image_paste_failed`, `text_paste_failed`, `enter_failed` | 실행 중에 다른 창을 눌렀거나, 카카오톡이 앞에 없었습니다. 실패 방만 다시 실행하면 됩니다 |
| 검색 중에 친구 추가 창이 열림 | 검색 클릭 위치가 어긋난 것입니다. `config\coords.yaml`을 그 PC에서 다시 맞춰야 합니다. 수집 담당에게 알립니다 |
| 글이 입력칸이 아닌 곳에 들어감 | `config\coords.yaml`의 `# message_input` 줄 주석을 지우고, 그 PC 방 창의 입력칸 좌표로 바꿉니다. 좌표를 비워 두면 방 창 하단 가운데를 누릅니다 |
| 스케줄 시각이 됐는데 아무 일도 없음 | PC가 잠겨 있거나 로그오프 상태입니다. 작업은 로그온 중에만 카카오톡을 누를 수 있습니다. 작업 마지막 실행 결과를 작업 스케줄러에서 확인합니다 |

수집용 좌표를 홍보 때문에 임의로 많이 바꾸면 포스터 수집 클릭도 어긋납니다. `message_input`만 홍보 입력칸용이고, 나머지 좌표는 수집과 같이 씁니다.

## 10. 하지 않을 일

- 수집 작업이 실행 중일 때 홍보를 실행하지 않습니다.
- `.env`에 홍보 문구를 넣지 않습니다.
- `config\promo.example.yaml`을 운영 파일로 직접 고치지 않습니다. `data\promo`로 복사해서 고칩니다.
- 성공한 방이 있는데 기록 파일 전체를 지우면서 문구만 고치지 않습니다. 이미 받은 방에 같은 홍보가 한 번 더 나갑니다.
- 스케줄 인수에 `--force`나 `--now`를 넣지 않습니다.
